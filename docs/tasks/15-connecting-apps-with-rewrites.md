## Findings

- **`BLOG_URL` is read at build time.** The rewrite destination is baked into `routes-manifest.json`. Verified: a build with `BLOG_URL=http://localhost:3999` writes `:3999` destinations, and `/blog` returns 500 when that port is down. So on Vercel, `BLOG_URL` must be set for the web project's **build** (the lesson's "Redeploy the web project" step) — setting it only at runtime does nothing.
- **Blog links needed no change.** The blog's `href`s are plain strings (`/${post.slug}`, `/`), and the HTML already contains `/blog/…`. The lesson's note that `next/link` adds the prefix holds for the Links used here (confirmed in the browser: clicking a post goes to `/blog/<slug>`, and "Back to posts" points to `/blog`). No `<a>` in the blog needed the prefix added by hand.
- **Dev servers had to be restarted** (3000 and 3001). Rewrites and `basePath` are loaded at startup.
- **`next dev` generates `apps/<app>/AGENTS.md`** (an agent-rules pointer to the bundled Next docs). Ignored in both apps' `.gitignore`; the root `AGENTS.md` stays tracked.
- **Known gap, unchanged:** `/blog/does-not-exist-xyz` returns 200, because `fetchPostBySlug` invents a post for any slug (task 03). A real 404 under `/blog` needs the API change.
- The lesson's `vercel.json` was not added (the lesson says the legacy `builds`/`routes` form is unnecessary; this repo's root `vercel.json` is only a schema stub).
